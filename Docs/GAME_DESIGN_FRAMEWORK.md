## 0. 文档定位与更新规则

本项目首先是一个用于系统学习 Unity 的长期实践项目，同时需要形成可放入简历、参加比赛、独立演示的完整作品。开发不以“功能越多越好”为目标，而以“每个阶段都有新知识、每个版本都可运行、最终有完整体验”为目标。

本文同时承担以下职责：

1. 游戏设计文档：定义玩家体验、玩法规则、内容与数值基线。
2. 技术设计文档：定义模块边界、数据流和迭代方向。
3. 学习路线图：标注应由开发者亲自完成的学习型任务。
4. 项目管理基线：定义阶段目标、验收标准和停止扩张条件。
5. 能力档案：随着开发者掌握情况动态调整任务归属和难度。

### 0.1 本文不是不可修改的合同

以下情况出现时，应修改本文，而不是让代码勉强服从过时设计：

- 实际试玩证明机制不好玩或数值无法成立。
- 开发者已经掌握某知识点，需要提高任务难度或减少 AI 帮助。
- 某功能只有重复劳动，没有新增学习价值或展示价值。
- 移动端性能、比赛规则或时间限制要求缩小范围。
- 当前架构无法清晰支持下一阶段，且重构收益大于成本。

每次重要修改都应更新文末的“决策记录与变更日志”。知识掌握表建议每完成一个里程碑更新一次。

### 0.2 任务责任标记

- `【你主导】`：开发者负责设计、实现、调试并能在面试中解释。AI 可以提问、提示、评审，但不直接替代思考过程。
- `【协作完成】`：开发者先给出思路或首版实现，AI 负责代码审查、定位风险、补充边界情况与重复测试。
- `【AI 可代办】`：模板化、机械性或高重复工作可交给 AI，开发者只需理解用途并完成验收。
- `【后续学习】`：当前版本不引入，达到前置条件后再开启。

原则：任何进入项目的核心代码，开发者都必须能够解释其生命周期、数据流、关键边界和设计取舍。AI 生成不等于无需理解。

## 1. 产品愿景

### 1.1 一句话介绍

玩家在伤口与人体组织中部署拟人化免疫细胞，利用速射、减速、腐蚀、控制、吞噬和精准拦截等协同机制，对抗沿组织通道入侵的病原体，并在战斗中了解经过明确标注的基础免疫学知识。

### 1.2 项目目标

项目按优先级有四个目标：

1. **学习目标**：覆盖 Unity 常用工作流、C# 游戏实践、架构、调试、性能与发布。
2. **作品目标**：形成一段 10-20 分钟内能够展示核心卖点的高完成度纵向切片。
3. **比赛目标**：具备明确主题、完整循环、视觉反馈和可说明的创新点。
4. **长期目标**：如果新内容能持续引入有价值的新知识，则扩展为多关卡作品；否则在三关后收束。

### 1.3 核心体验支柱

1. **免疫反应链**：塔不是彼此无关的炮台，而是组成“识别 -> 信号 -> 效应 -> 清除/记忆”的细胞协作网络。
2. **清晰反馈**：攻击、命中、状态、资源变化、敌人泄露和波次压力都必须一眼可读。
3. **有限空间决策**：固定塔位让位置与组合比铺满地图更重要。
4. **生物主题机制化**：知识不只出现在文字中，还应尽量转化为玩法关系。
5. **稳态取舍**：更强烈的免疫反应能解燃眉之急，却会积累炎症并伤害组织；玩家追求的是有效防御，不是无限堆火力。
6. **易上手、有深度**：首关能快速理解，群落行为、反应链、升级分支、技能选择和多路线逐步增加决策。

### 1.4 目标玩家

- 喜欢轻度或中度策略塔防的玩家。
- 对生物、细胞或科普题材感兴趣的玩家。
- PC 与手机上的短局体验玩家。
- 比赛评委和招聘方：需要快速看懂项目亮点与开发能力。

### 1.5 美术与叙事调性

- 视角：2D 俯视平面。
- 风格：无阴影或弱阴影的扁平生物手绘/矢量风格。
- 情绪：轻松卡通的角色表现 + 波次推进的紧张战斗 + 克制关系中的科学启发。
- 科学边界：所有拟人化、武器化和简化机制必须与真实知识分开标注，避免把玩法虚构表述为医学事实。
- 制作策略：开发期先使用几何图形和明确标注的占位素材，核心玩法稳定后再使用合规 AI 素材或寻找美术合作。

统一色板、镜头、轮廓、生产规格与资产验收以 [ART_DIRECTION.md](ART_DIRECTION.md) 为准；塔、敌人、地图和子弹/特效的提示词分别存放在 `Docs/Prompts/`，禁止把不同类别重新混成一个提示词文档。

## 2. 版本范围与扩展原则

### 2.1 最小完整作品：三关纵向切片

三关必须形成可独立发布的 Demo，不依赖“以后会做”的内容才能成立。

| 关卡 | 地图结构 | 主要玩法 | 新增学习主题 | 展示目标 |
|---|---|---|---|---|
| 第一关：伤口表层 | 单入口、单路线 | 建造、升级、出售、基础克制、Boss | Prefab、ScriptableObject、对象池、UGUI、协程、基础事件 | 完整核心循环 |
| 第二关：组织深层 | 多入口汇合 | 多路线压力、状态效果、主动技能、精英怪 | 路径图、状态系统、动画、粒子、音频、JSON 存档 | 系统组合与表现力 |
| 第三关：血管防线 | 分叉与动态事件 | 分支升级、复杂 Boss、战前配置、综合挑战 | 状态机、Timeline、本地化、移动适配、Profiler、测试 | 简历/比赛完成度 |

首个可玩版本优先短局：第一关目标时长暂定 6-8 分钟。核心循环稳定后，第二关暂定 10-12 分钟，第三关暂定 12-15 分钟；最终以试玩中的决策密度和疲劳程度调整，而不是单纯增加波次拖长时间。

### 2.2 长期扩展门槛

第三关完成后，只有满足以下至少一项才新增大内容：

- 引入此前未实践的技术，例如 A*、关卡编辑器、程序化关卡、Addressables、联网排行榜或云存档。
- 形成明显不同的策略体验，而不是只修改敌人血量和数量。
- 能提高参赛、作品集或发布价值。
- 现有玩家反馈明确支持扩展。

若新增内容主要是复制关卡、复制塔或批量调数值，则优先完善画面、手感、性能、测试和展示材料，并在三关处结束。

### 2.3 明确不在首版强求的内容

- 联机与多人协作。
- 付费、广告和服务器账户。
- 复杂 ECS/DOTS 架构。
- 全动态自由建造与实时改路。
- 大规模程序化地图。
- 完整医学教学课程。

这些内容可以作为独立学习分支，但不能阻塞三关 Demo。

## 3. 核心游戏循环

### 3.1 局外循环

```text
主菜单 -> 选择关卡与技能 -> 战斗 -> 结算评价
   ^                              |
   |---- 图鉴/解锁/设置/重试 <----|
```

玩家通过关卡结算获得免疫记忆点，用于解锁新塔、主动技能、图鉴和少量基础强化，再挑战更复杂的地图。

### 3.2 局内循环

```text
观察路线、病原群落与信号网络
  -> 消耗 ATP 在固定组织节点部署免疫单元
  -> 建立识别/信号/效应/清除反应链
  -> 在杀伤效率与组织稳态之间调节炎症
  -> 升级、改变链路重点或释放生物酶技能
  -> 提前开始下一波：获得 ATP，但放弃部分炎症恢复
  -> 击败 Boss 或组织生命归零
```

### 3.3 核心差异：免疫反应链

本作的最小创新单位不是“一个新塔”，而是一条由不同塔完成的免疫反应。敌人默认不是已经被所有塔完全识别的血条；塔阵需要先发现特征，再把信息传给真正适合处理它的细胞。

```text
病原体进入
  -> 识别塔取得抗原样本
  -> 信号节点把样本传给相连塔位
  -> 抗体/效应塔把样本转化为标记、破膜或控制
  -> 巨噬细胞完成清除并回收生物酶
  -> 同类病原获得短时“免疫记忆暴露”
```

#### 玩家能直接看懂的三层信息

| 层 | 表现 | 规则 |
|---|---|---|
| 未识别 | 敌人无轮廓标记 | 塔仍可造成基础伤害，但无法触发高级协同 |
| 已采样 | 敌人出现白色抗原碎片图标 | 信号网络能把该类型信息传给其他节点 |
| 已标记 | 敌人出现高对比抗体环 | 效应塔触发各自的“标记反应”，清除后形成记忆脉冲 |

不再额外堆叠十几个玩家必须背诵的反应名称。底层可以有状态对象，界面只展示这三个识别阶段和最重要的一个异常状态。

#### 固定塔位为什么重要

地图上的塔位同时是“组织信号节点”，节点之间有预先设计的可见连接线。塔能把抗原信息传给直接相连节点，但不能全图共享。玩家因此需要决定：

- 把识别塔放在入口，尽早采样，还是放在汇合点覆盖更多路线。
- 把有限的高活性节点给输出塔，还是给能把两条支路信号合并的 B 细胞。
- 让巨噬细胞靠近末端保证清除，还是靠近效应区回收更多生物酶。
- 感染节点被净化后，是补断开的链路，还是增加独立火力。

信号网络是地图预制的无向/有向小图，不允许玩家自由拉线。首关只展示一条 4–6 节点的简单链，第二关才出现汇合，第三关出现可切换信号阀。这既提供图论、数据驱动地图和可视化学习点，也避免变成复杂电路模拟器。

#### 代表性反应组合

| 名称 | 触发 | 结果 | 设计目的 |
|---|---|---|---|
| 抗原接力 | 中性粒细胞采样后，样本到达抗体 B 细胞 | 同类型敌人被高效标记 | 鼓励入口识别与后段处理 |
| 破膜吞噬 | 溶酶体酸化炮破坏群落防护，巨噬细胞命中 | 提高吞噬阈值并回收少量生物酶 | 让重甲处理不是单纯堆 DPS |
| 神经同步 | 已标记群落受到神经脉冲 | 电弧优先沿同一群落传播并打断集结 | 把连锁目标与群落系统结合 |
| 凝血隔离 | 纤维蛋白壁垒覆盖已采样群落 | 降低其群落感应增长，少量降低炎症 | 防御塔不仅是传统减速塔 |
| 免疫记忆 | 已标记敌人被清除 | 邻近同类短时自动进入已采样 | 形成“越理解越高效”的战斗节奏 |

反应组合的原则是改变目标选择、群落行为或资源循环，而不是只弹出一个额外伤害倍率。

### 3.4 核心差异：病原群落会组织起来

敌人不是独立排队的血包。同一 `PathogenCohort` 的单位靠近时会积累“群落感应”，达到阈值后触发可预览的群落行为：

| 群落行为 | 触发与表现 | 玩家应对 |
|---|---|---|
| 生物膜 | 密集慢速群形成半透明外膜，共享有限护盾 | 破膜、隔离、分散处理，不靠硬免疫 |
| 集群冲刺 | 高速群完成信号同步后短时加速 | 提前采样、凝血隔离、精准拦截 |
| 孢子播散 | 真菌单位死亡时若群落感应过高，释放少量孢子 | 在成群前清除、控制死亡位置 |
| 质粒适应（玩法改编） | 连续波次受到同一压力时，下波出现一种可见软适应 | 根据预览调整塔组，不产生完全免疫 |

群落感应按“群组 + 区域”低频计算，不做每个敌人与所有邻居的逐帧距离判断。视觉上以群落连线、外膜和头顶单一量表表现，避免大量图标遮挡。

### 3.5 核心差异：炎症与组织稳态

炎症值为 0–100 的局内公共状态。它不是第四种消费货币，而是玩家行为造成的系统压力：

| 区间 | 状态 | 效果 |
|---:|---|---|
| 0–34 | 平稳 | 无惩罚，适合重建链路与积累资源 |
| 35–69 | 有效应答 | 效应塔小幅提速，生物酶获取效率提高；这是理想区间 |
| 70–89 | 过度炎症 | 组织恢复停止，敌人群落适应加快，画面出现明确预警 |
| 90–100 | 细胞因子风暴（玩法改编） | 周期损失组织生命；强力塔继续增益但风险急剧增加 |

炎症来源：酸化、电击、全图技能、敌人泄露、连续提前开波。炎症降低：自然波间恢复、凝血隔离、巨噬细胞完成已标记清除，以及少量关卡事件。

提前开波现在有双重取舍：立刻获得 ATP 并提高节奏，但会保留当前炎症、提高群落重叠概率。玩家不是每次看到按钮都必然点击。

炎症不会在首关开局全部开放。第一关 Wave 3 通过一次脚本化过激事件教学；第二关开始成为完整系统。教学/休闲模式将危险阈值提高并提供更长恢复时间。

### 3.6 质粒适应与反套路规则

每一波统计玩家施加的主要免疫压力，但只允许下一波获得一个预告明确的软适应：

- 物理压力过高：部分群落获得可被酸化破坏的薄膜。
- 化学压力过高：敌人更分散，降低酸池覆盖效率，但单体生命不额外暴涨。
- 电击压力过高：群落间距变化，连锁距离缩短。
- 吞噬压力过高：少量单位提高吞噬阈值，但仍可用标记/破膜恢复处理效率。

规则必须遵守：

1. 玩家在下一波预览中提前看到适应名称、图标和原因。
2. 适应只改变阵型或一个机制，不同时叠血量、速度和抗性。
3. 不产生 100% 免疫，不让战前六选四因隐藏信息直接失败。
4. Boss 的阶段变化由脚本固定，不读取玩家数据作弊。
5. 第一关仅展示预设适应，第二关再启用压力统计，第三关允许玩家用技能误导或重置一次适应。

### 3.7 单局流程状态

游戏流程不应只依赖 `Time.timeScale` 判断，应建立明确状态：

```text
Loading -> Preparation -> WaveCountdown -> Combat
                       ^          |           |
                       |          v           v
                       +------ Intermission   Paused
                                      |         |
                                      v         |
                               Victory / Defeat <-+
```

建议状态枚举：

```csharp
public enum GameState
{
    Loading,
    Preparation,
    WaveCountdown,
    Combat,
    Intermission,
    Paused,
    Victory,
    Defeat
}
```

`【你主导】` 实现状态转换与允许操作规则；`Time.timeScale` 只负责暂停时间流动，不承担完整游戏状态。

### 3.8 胜负规则

- 普通敌人抵达终点后按自身 `leakDamage` 扣除生命值并离场。
- Boss 抵达终点同样扣除生命值，不直接强制失败。
- 生命值小于等于 0 时失败。
- 所有波次生成完毕且场上存活敌人为 0 时胜利。
- 胜负只允许结算一次。
- 暂停、胜利和失败状态下禁止建造、升级、出售与释放技能。

失败后可以立即重试或返回选关，但标准和挑战难度不允许从中间波次继续。教学/休闲难度每局允许一次“免疫复苏”，从当前波开始前的安全快照恢复；该功能必须明确标为教学辅助，不能计入挑战成绩。

### 3.9 难度模式

| 模式 | 用途 | 调整原则 |
|---|---|---|
| 教学/休闲 | 学习机制和阅读科普 | ATP 更充足、提示更详细、允许一次免疫复苏 |
| 标准 | 默认设计与比赛演示 | 使用正式数值，不提供中途续波 |
| 挑战 | 熟练玩家与额外奖励 | 调整敌群组合、能力和资源压力，避免只增加生命值 |

难度差异由 `DifficultyDefinition` 配置。挑战难度可以奖励额外免疫记忆点或外观内容，但不应成为解锁核心玩法的唯一途径。

### 3.10 原创性护栏与最小特色切片

本作不能只在传统“造塔 -> 自动射击 -> 升级伤害 -> Boss”循环上替换细胞皮肤。第一关纵向切片至少包含：

1. 一张可见的 4–6 节点组织信号图。
2. 中性粒细胞采样、B 细胞标记、至少一种效应反应和巨噬细胞清除的完整链。
3. 一种病原群落行为（首选生物膜）和一种隔离/打断手段。
4. 炎症的有效应答与过度炎症两个区间。
5. 一次真正有可能“不该提前开波”的取舍。

第一关不启用动态软适应；它只展示一段固定演出。第二关再读取上一波压力，避免新玩家同时学习太多系统。

#### 设计否决条件

- 如果把细胞名称全部换成弓箭、冰塔和兽人后，玩法关系完全不变，则该机制不够主题化。
- 如果最优解长期是把四个最高 DPS 塔放在终点，则信号网络和群落机制没有成立。
- 如果反应组合最后都只等价为“额外 X% 伤害”，则需要重做至少一半组合。
- 如果玩家为了避免惩罚总想把炎症维持在 0，则有效应答区收益不足；如果始终保持 100，则风险不足。
- 如果动态适应让玩家感觉系统在暗中针对自己，而不是提前给出可利用的信息，则退回固定波次。
- 如果信号线和群落图标让玩家看不清路径/敌人，先简化表现，不继续增加状态。

#### 试玩成功信号

- 首次玩家能在 10 分钟内用自己的话说明“采样、传递、标记、清除”的关系。
- 玩家至少构筑出两种有效链路，而不是所有人复制唯一终点阵。
- 玩家会根据群落行为改变处理顺序，而非只盯单体血量。
- 一局中至少出现一次主动接受较高炎症以换取收益，以及一次主动降温的行为。
- 失败后玩家能指出是链路断裂、群落成型、炎症失控或资源判断之一，而不是只说“数值不够”。

## 4. 地图、路线与固定塔位

### 4.1 建造规则

- 玩家只能在设计阶段预先放置的 `BuildSlot` 上建塔。
- 路径与普通背景不生成可点击网格。
- 塔位必须清楚显示空闲、悬停、选中、不可用和占用状态。
- 建造前提供塔的范围预览、费用和主要定位。
- 塔出售或被关卡机制移除后，原 `BuildSlot` 必须恢复为可用状态。
- PC 使用鼠标，手机使用单指点击；输入系统改造放在核心循环稳定之后。

### 4.2 塔位类型

| 类型 | 规则 | 设计用途 |
|---|---|---|
| 普通组织位 | 可放置所有远程/辅助塔 | 基础决策 |
| 近路吞噬位 | 靠近路线，允许巨噬细胞并提供近战空间 | 强调位置限制 |
| 信号枢纽位 | 与三个以上组织节点连接，信号传递效率高 | 争夺网络中心而非单纯最佳输出点 |
| 活性组织位 | 提供小幅效应速度，但会产生更多炎症 | 制造火力与稳态的取舍 |
| 感染塔位 | 初始锁定，花费 ATP 或技能净化后使用 | 增加关卡节奏 |

首关只使用普通位和少量近路位；第二、三关再逐步加入特殊类型。

### 4.3 路线技术递进

1. 首关使用有序 Waypoint 数组，学习基础移动和编辑器配置。
2. 第二关使用路径图节点，支持多入口汇合。
3. 第三关使用可选择分支的路径图，并允许关卡事件切换部分路径。
4. `【后续学习】` 在挑战模式实现 A*，用于动态障碍或会主动绕路的特殊敌人。

A* 不应为了“架构高级”提前加入，因为固定塔位与固定路线并不需要它；应等到玩法真正需要动态寻路时再实现。

## 5. 资源与经济系统

### 5.1 三种资源

| 资源 | 局内/局外 | 获得方式 | 用途 |
|---|---|---|---|
| ATP | 局内 | 初始资金、完成有效清除、教学被动恢复、提前开波奖励 | 建塔、升级、净化塔位 |
| 生物酶 | 局内 | 精英怪、Boss 阶段掉落或波次奖励 | 主动技能 |
| 免疫记忆点 | 局外 | 关卡结算、挑战目标 | 解锁塔、技能、图鉴与轻量强化 |

### 5.2 首版经济基线

- 初始生命值：20。
- 第一关初始 ATP：150。
- 击杀收益：`基础奖励 + floor(当前波次索引 × 0.5)`。
- 被动恢复：标准与挑战模式不持续恢复；教学/休闲模式可以每秒缓慢恢复 1 ATP。
- 提前开波：`奖励 ATP = floor(剩余秒数 × 关卡系数)`；第一关系数暂定为 1，同一波只能领取一次且连续提前不开额外倍率。
- 出售返还：累计建造与升级消耗的 70%，向下取整。
- 免疫记忆点：依据通关、剩余生命和挑战目标结算。

所有数值均为可试玩基线，不是最终平衡。数值必须通过 ScriptableObject 或关卡数据配置，不散落在代码里。

### 5.3 经济不变量

`【你主导】` 明确并实现以下规则：

- 余额永不因正常操作小于 0。
- 一次购买只扣款一次。
- 升级失败不改变等级与余额。
- 出售价值来自真实累计投入，不依赖可能变化的当前配置值。
- 结算后不再产生局内资源。
- ATP、生物酶与免疫记忆点使用不同的数据类型和接口，避免混用。

## 6. 防御塔系统

### 6.1 通用规则

- 所有塔包含等级、造价、射程、攻击间隔、目标策略、累计投入和当前状态。
- LV1 为基础形态；LV2 为固定强化；LV3 选择两个互斥分支之一。
- 分支选择后不可在局内切换，出售后重新建造可重选。
- 控制与伤害行为优先使用组合式策略，避免把全部特殊逻辑塞进一个巨型 `BaseTower`。
- 目标策略至少支持：最接近终点、最近、最低生命、最高速度、带护盾优先。
- 教学流程按波次提供指定塔；首次通关后，常规关卡在战前从已解锁的六塔中选择四塔携带。
- 每座塔还具有反应角色：识别、调节、效应、清除或记忆；升级分支必须至少改变一种反应关系，不能全部只加伤害。
- 设计稿中的中文名是玩家可见名称。现有代码枚举/文件名可暂时保留旧 ID，数据迁移时建立明确映射，不通过重命名 `.asset` 猜测引用关系。

### 6.2 六种塔与分支

| 塔 | LV1 定位与基线 | LV2 固定升级 | LV3-A | LV3-B |
|---|---|---|---|---|
| 中性粒细胞哨兵（旧 ID：SentryTCell） | 100 ATP；8 伤害；0.25 秒；3.5 格；速射并采集抗原样本 | 80 ATP；间隔降至 0.18 秒，采样保持更久 | **NET 捕获**：样本沿信号链传播并短时限制群落感应 | **精准趋化**：降低射速，提高单发和精英采样效率 |
| 纤维蛋白壁垒（旧名：生物壁垒细胞） | 120 ATP；半径 2.5；范围减速 40%，抑制群落感应 | 90 ATP；减速提高至 55%，少量降低炎症 | **隔离纤维**：切断敌群间的群落信号 | **稳态凝固**：周期性定身更短，但炎症调节更强 |
| 溶酶体酸化炮（旧名：酸性 B 细胞） | 150 ATP；直击 15；每秒 10，持续 3 秒；破坏生物膜 | 110 ATP；酸化区域持续 5 秒 | **破膜酸化**：显著降低群落护盾并提高吞噬阈值 | **定向囊泡**：范围缩小、污染更少，对已标记目标更强 |
| 神经脉冲刺突（旧名：神经刺客） | 200 ATP；45 伤害；20% 跳跃衰减；短暂停顿；优先同群落传导 | 140 ATP；最大传导目标 5 | **信号封锁**：打断一次集群行为，控制时间提高 | **同步电弧**：已标记群落中的跳跃衰减降低 |
| 巨噬细胞清道夫（旧名：吞噬者） | 180 ATP；清除低于阈值的小怪；Boss 转为 150 伤害；冷却 4 秒 | 120 ATP；冷却降至 2.5 秒；标记清除降低炎症 | **消化回收**：完整反应链清除后获得生物酶 | **巨物裂解**：无法吞噬时按最大生命比例造成有限伤害 |
| 抗体 B 细胞中继（旧名：病毒拦截者） | 160 ATP；30 伤害；把相连节点的样本转化为抗体标记；射程 5 | 100 ATP；标记可剥离护盾/加速 | **克隆记忆**：标记清除产生更强的同类记忆脉冲 | **连续中继**：击杀后把标记快速转移给同群落目标 |

这些分支需要通过试玩调整，尤其要避免硬控制无限叠加、吞噬对 Boss 生效、标记链自动滚雪球和炎症收益覆盖全部代价。旧名只用于和当前原型对照，正式 UI、图鉴与提示词采用新名称。

### 6.3 塔状态

- 正常、攻击冷却、升级选择、眩晕/瘫痪、出售中。
- Boss 的塔瘫痪属于可视化状态效果，必须有图标、倒计时或明显特效。
- 塔被瘫痪时不攻击，但 UI 和点击仍可响应。

### 6.4 锁敌原则

默认策略是“路径进度最高”，即最接近终点，而不是空间距离最近。不同塔可覆盖默认策略：

- 抗体 B 细胞中继：已采样目标 > 护盾目标 > 群落感应最高。
- 巨噬细胞：可吞噬目标 > 生命值最低目标 > 路径进度最高。
- 神经脉冲刺突：能形成最多同群落连锁的目标优先。

`【你主导】` 编写目标评分或策略接口，这是接口、组合、算法思维和面试表达的重要实践。

### 6.5 伤害类型与结算

首版采用四种正式伤害类型：

| 类型 | 主要来源 | 规则定位 |
|---|---|---|
| 物理 | 中性粒细胞哨兵、部分 Boss 攻击 | 稳定直接伤害，受到护甲减免 |
| 化学 | 溶酶体酸化炮 | 持续伤害与破膜，适合重甲和集群，但增加炎症 |
| 电击 | 神经脉冲刺突 | 连锁、打断和控制，伤害逐次衰减并增加炎症 |
| 吞噬 | 巨噬细胞 | 对阈值以下普通敌人处决；对 Boss 转化为有限普通伤害 |

克制采用倍率、护甲和状态效果，不设计因塔型错误而完全无法造成伤害的硬免疫。建议伤害结算顺序为：基础伤害 -> 来源增减益 -> 目标护甲/抗性 -> 易伤 -> 最低伤害保护 -> 生命扣减。精确公式在完成首轮战斗沙盒后确定。

`【你主导】` 将结算写成尽量独立于 MonoBehaviour 的普通 C# 逻辑，并能解释结算顺序为什么会影响平衡。

## 7. 敌人与状态系统

### 7.1 首关核心敌人

| 敌人 | 定位 | HP | 速度 | 奖励 | 泄露伤害 | 特性 |
|---|---|---:|---:|---:|---:|---|
| 葡萄球菌 | 基础杂兵 | 50 | 2.0 格/秒 | 10 ATP | 1 | 数量多，无特殊抗性 |
| 鞭毛双球菌 | 高速单位 | 30 | 4.5 格/秒 | 12 ATP | 1 | 需要减速或拦截 |
| 破伤风梭菌 | 重甲单位 | 400 | 1.0 格/秒 | 35 ATP | 3 | 高护甲，弱于腐蚀和吞噬 |
| 变异超级真菌 | Boss | 2500 | 0.8 格/秒 | 200 ATP | 20 | 每损失 30% 生命分裂小怪并瘫痪一座塔 3 秒 |

说明：以上为玩法拟人化名称和机制，不应在图鉴中直接宣称为严格免疫学事实。

### 7.2 后续敌人维度

后续扩展优先新增机制维度，而不是只提高血量：

- 护盾/包膜，需要抗体 B 细胞中继标记或溶酶体酸化炮破膜。
- 治疗或增益周围病原体。
- 对特定控制产生抗性。
- 死亡后分裂或留下污染区域。
- 周期性改变路线或短距离冲刺。

敌人能力优先服务群落系统：新敌人应改变聚集、采样、信号、标记或清除中的至少一个环节。若只是“更高生命 + 更高速度 + 新颜色”，不进入正式三关。

### 7.3 通用状态效果

建议建立统一状态系统：

- 减速、眩晕、易伤、破甲、标记、加速、狂暴、护盾、持续伤害。
- 每个状态明确持续时间、来源、叠加方式、刷新方式和最大层数。
- 同类减速首版采用“取最高值并刷新持续时间”，避免乘法叠加导致速度接近 0。
- 眩晕需要控制抗性或短暂免控，避免永久控制。
- DOT 记录来源，保证击杀奖励和统计正确。

`【你主导】` 先设计状态规则和最小接口；`【协作完成】` 由 AI 补充重复状态类、边界检查和测试用例。

## 8. 波次与关卡设计

### 8.1 波次规则

- 波次默认在倒计时结束后自动开始。
- 波间阶段允许玩家提前开始下一波并获得奖励。
- 当前波与下一波敌情必须可预览。
- 多入口波次的数据应能配置每个生成组的入口、敌人、数量、间隔和起始偏移。
- 波次系统通过事件报告开始、生成结束、敌人清空和关卡完成，不直接操作所有 UI。

### 8.2 第一关：伤口表层

第一关保持单路线、5 波，完成基础教学：

| 波次 | 敌人构成 | 目的 |
|---|---|---|
| 1 | 葡萄球菌 × 8 | 教学：哨兵采样与基础信号线 |
| 2 | 葡萄球菌 × 10 + 高速菌 × 4 | 教学：减速与优先目标 |
| 3 | 重甲菌 × 2 + 葡萄球菌 × 10 | 教学：破甲/吞噬 |
| 4 | 高速菌 × 12，分两组 | 检验群落感应、隔离与神经同步 |
| 5 | Boss × 1 + 伴随杂兵 | 综合检验，介绍塔瘫痪 |

首关不一次开放六塔，按以下顺序提供教学试用：

- 开局：中性粒细胞哨兵、纤维蛋白壁垒。
- Wave 2 后：溶酶体酸化炮。
- Wave 3 后：巨噬细胞清道夫，并教学炎症恢复。
- Wave 4 前：神经脉冲刺突、抗体 B 细胞中继。
- 首次通关后：六塔成为后续标准关卡的常规可用内容。

首次流程中的临时开放不应要求玩家返回菜单操作；永久解锁状态写入存档。

### 8.3 第二关：组织深层

- 两个入口汇合到一个终点。
- 引入感染塔位、精英单位、主动技能和状态叠加。
- 玩家需要判断两个入口的压力，而不只是守住路线末端。
- 首次保存关卡成绩、图鉴和解锁数据。
- Boss 为“细菌生物膜核心”：为周围敌人提供护盾与恢复，并周期性制造感染区域。重点学习支援型 Boss、护盾和区域效果。

### 8.4 第三关：血管防线

- 路线包含分叉，关卡事件可改变部分敌人的选择。
- 完整开放 LV3 二选一分支。
- Boss 为“病毒母体”：根据生命阶段发生变异、改变自身能力并影响路线选择。使用多阶段状态机，并通过 Timeline 或镜头演出强化阶段转换。
- 完成移动端布局、触控验证、本地化和性能优化。
- 路线变化由 Boss 或关卡事件自动触发，并在变化前清楚预警；玩家主动控制路线留给后续挑战模式。

三关各有一名机制不同的 Boss：第一关的变异超级真菌负责分裂与塔瘫痪，第二关的生物膜核心负责护盾与恢复，第三关的病毒母体负责多阶段变异与路线变化。

## 9. 主动技能与局外成长

### 9.1 生物酶技能

首版设计 3 个技能，关卡开始前选择 2 个携带：

| 技能 | 作用 | 学习/设计价值 |
|---|---|---|
| 发热反应 | 全图持续伤害，并小幅影响敌人速度 | 全局效果、DOT、全屏反馈 |
| 抗体轰炸 | 指定区域爆发伤害并剥离护盾 | 范围选择、预览、触控交互 |
| 凝血封锁 | 指定路径区短时间大幅减速，不永久堵路 | 路径区域、时限状态、平衡约束 |

技能消耗生物酶并具有冷却时间。技能不能直接成为“无脑清屏按钮”，应解决紧急情况或补足塔阵弱点。

### 9.2 免疫记忆点

以内容解锁为主，永久数值强化为辅：

- 解锁新塔与新技能。
- 解锁科普图鉴和挑战模式。
- 提供小幅、可封顶的初始 ATP 或基础生命强化。
- 关卡标准模式应能在不依赖大量永久强化时通关，确保比赛展示与平衡公平。

永久数值强化总幅度暂定封顶在 10%-15%，具体上限通过标准模式试玩验证。主要成长价值来自内容解锁和策略选择，而非反复刷取数值碾压关卡。

关卡采用三星评价：完成关卡获得 1 星；达到剩余生命要求获得第 2 星；完成关卡专属挑战获得第 3 星。免疫记忆点主要根据首次获得的新星发放，避免通过反复刷简单关卡无限积累。挑战条件可以是限制泄露、限定塔种、限定时间或限制主动技能，但必须在开始前明确展示。

### 9.3 存档范围

首版 JSON 存档包括：

- 存档版本号。
- 已通关关卡、星级和最佳成绩。
- 免疫记忆点。
- 已解锁塔、技能和图鉴。
- 音量、语言和基础设置。

首版只提供一个自动存档档案和“重置进度”功能，不开发多个存档槽。每次结算、解锁和设置变更后保存；写入失败不得破坏上一份有效数据。

`【你主导】` 定义存档模型、版本号和迁移思路；`【协作完成】` AI 可帮助写重复序列化字段、异常保护和测试数据。

## 10. 科普呈现

### 10.1 三层信息结构

1. **战斗内短提示**：用一句话解释克制，例如“酸性环境会削弱该敌人的防护”。
2. **首次遇见知识卡**：可暂停、可跳过，不在高压战斗中强迫阅读。
3. **图鉴**：分别显示“真实知识”和“游戏化改编”。

### 10.2 内容模板

每个塔和敌人的图鉴包含：

- 游戏定位。
- 真实生物学概念。
- 游戏化改编说明。
- 克制与被克制关系。
- 信息来源占位，正式参赛或发布前补充可信来源。

### 10.3 科普原则

- 不提供医疗诊断或治疗建议。
- 不把 T 细胞、B 细胞等真实功能等同于游戏中的枪械、酸池等表现。
- 对明显虚构机制使用“本游戏中”“玩法设定”措辞。
- 科普内容必须经过来源核对；AI 可协助整理，但不能作为唯一事实来源。

## 11. UI、操作与反馈

### 11.1 必要界面

- 主菜单、选关、技能配置、设置、图鉴。
- 局内 HUD：生命、ATP、生物酶、当前波、下一波、速度、暂停。
- 建造菜单、塔详情、升级分支、出售确认。
- 胜利、失败、结算与奖励页面。
- 新手引导和知识卡片。

建造交互同时支持两种路径：手机主要点击空塔位后打开可建塔列表；PC 额外支持先从工具栏或快捷键选择塔，再点击塔位。点击已有塔统一打开详情、升级分支和出售面板。

### 11.2 PC 与手机布局

- PC：鼠标点击、悬停提示、数字快捷键作为增强功能。
- 手机：采用横屏；单指点击、足够大的触控区域、安全区适配，不依赖悬停。
- 第一关使用固定镜头，保证学习阶段交互简单；第二、三关根据地图尺寸加入单指拖动与双指缩放。
- 首先保证 16:9 PC 和常见手机宽高比，之后测试异形屏与不同 DPI。
- 核心循环稳定后再迁移 Unity Input System，统一鼠标与触控；当前阶段不让输入迁移阻塞玩法实现。

### 11.3 UI 学习重点

`【你主导】` 亲自完成至少一个完整自适应界面，理解而不是只记参数：

- Anchor 决定控件随父容器哪部分变化。
- Pivot 决定控件自身的旋转、缩放和定位参考点。
- Anchored Position 是相对锚点的偏移。
- Layout Group、Content Size Fitter 与 Aspect Ratio Fitter 的职责和常见冲突。
- Canvas Scaler、参考分辨率、安全区与像素密度。
- UI 射线与游戏世界点击的隔离。

`【AI 可代办】` 在开发者完成并解释第一套规范布局后，AI 可按同一规范批量制作重复面板或绑定样板字段。

### 11.4 教程与无障碍

- 教程使用短步骤高亮，要求玩家亲自完成一次建造、升级、出售和技能操作。
- 教程可以临时暂停或降低局部流程压力，但科普卡片与操作教学分开。
- 完成教学后可在设置中关闭或重新开启引导。
- 状态不能只用颜色表达，必须同时使用图标、形状或文本。
- 首版支持 UI 字号缩放、关闭屏幕震动、独立音效音量和暂停菜单的非缩放时间交互。
- 中文为首发语言；第三关完成阶段补充英文并验证布局长度。

### 11.5 战斗反馈清单

- 子弹命中、伤害数字、暴击/克制颜色。
- 状态图标、叠层和剩余时间。
- 建造成功/失败、余额不足、塔位不可用提示。
- 敌人泄露时生命损失反馈。
- Boss 出场、阶段转换和技能预警。
- 音效、粒子、轻量屏幕震动与镜头强调。
- 提供减少震动、调节音量等设置。

首版暂不制作背景音乐或动态音乐系统，只保留对操作可读性重要的基础音效，例如建造、命中、资源不足、敌人泄露和胜负提示。音乐系统作为后续美术音频完善项，不阻塞玩法学习。

### 11.6 战斗统计与结算数据

结算页保留以下统计，并由统一战斗统计服务采集：

- 各塔总伤害、击杀数和控制时长。
- ATP 建造/升级支出、出售返还与提前开波收益。
- 各类敌人泄露数量和损失生命值。
- 主动技能造成的伤害、控制或护盾剥离贡献。
- 剩余生命、通关时间、难度和评价。

统计既用于玩家复盘，也用于数值平衡、Debug 和作品集展示。统计系统不得反向控制战斗规则，避免展示逻辑影响核心结算。

### 11.7 美术资产与授权

- 原型阶段允许使用自制几何图形、纯色 Sprite 和明确命名的占位资源。
- 正式替换可以使用自制、合法授权素材、AI 生成素材或美术合作成果。
- 每项外部资源记录来源、作者、许可、是否修改和可否用于比赛/商业展示。
- 使用 AI 资源时记录工具与用途，并在参加具体比赛前重新检查当届规则。
- 占位素材不得被误认为最终完成内容出现在正式宣传截图中。

## 12. 技术架构

### 12.1 架构目标

- 数据与运行时状态分离。
- 核心玩法可在不打开具体场景时进行部分验证。
- 管理器之间通过小型接口和事件协作，避免互相 `FindObjectOfType`。
- 先保持可理解，再逐步引入模式；不为了面试名词制造无必要抽象。

### 12.2 建议分层

```text
Presentation
  UI、动画、音效、粒子、镜头、输入
        |
Application
  游戏状态、关卡流程、建造、波次、存档协调
        |
Domain
  伤害、经济、升级、状态、目标选择、胜负规则
        |
Infrastructure
  Unity Prefab、ScriptableObject、对象池、JSON、场景加载
```

Unity `MonoBehaviour` 负责生命周期与场景桥接；可独立表达的规则尽量放进普通 C# 类，便于理解、调试和测试。

### 12.3 数据资产

建议使用：

- `TowerDefinition`：塔名称、等级属性、升级分支、Prefab、图标。
- `EnemyDefinition`：生命、速度、护甲、奖励、泄露伤害、能力标签。
- `WaveDefinition`：生成组、入口、数量、间隔、延迟。
- `LevelDefinition`：地图、初始资源、生命、波次、可用塔和技能。
- `SkillDefinition`：消耗、冷却、作用参数、图标和表现资源。

ScriptableObject 保存静态配置；当前生命、等级、冷却、状态等运行时数据不得写回共享资产。

建议正式资源目录：

```text
Assets/Data/Towers/
Assets/Data/Enemies/
Assets/Data/Waves/
Assets/Data/Levels/
Assets/Data/Skills/
```

例如第一座哨兵塔应通过 Unity 菜单创建为 `Assets/_Project/Data/Towers/SentryTowerDefinition.asset`。不要把数据资产放进 `Scripts/`，也不要在资源管理器里手工创建 `.asset` 文件。

### 12.4 运行时模块

| 模块 | 核心责任 | 推荐技术 |
|---|---|---|
| GameFlow | 状态转换、暂停、胜负、场景流程 | 有限状态机、事件 |
| Economy | 三种资源的增减与校验 | 普通 C# 服务、只读属性 |
| Build | 塔位、选择、建造、升级、出售 | 命令式操作、事件 |
| Wave | 波次调度、生成组、存活统计 | 协程或计时器、事件 |
| Enemy | 路径进度、生命、状态、泄露 | 组合式组件 |
| Tower | 锁敌、攻击、等级与分支 | 策略接口、组合 |
| Combat | 伤害、护甲、DOT、击杀归属 | 纯逻辑模型 |
| Pooling | 子弹、特效、敌人的复用 | 泛型池逐步演进 |
| Save | JSON、版本、迁移与容错 | DTO、文件服务 |
| UI | 状态展示与输入转发 | UGUI，后续局部 UI Toolkit |

### 12.5 事件边界

适合使用事件的通知包括：

- 游戏状态改变。
- 资源改变。
- 波次开始/结束。
- 敌人生成、死亡、泄露。
- 塔建造、升级、出售。
- 存档加载完成。

不应把所有调用都改成全局事件。需要立即返回结果的行为，例如“能否购买”“伤害结算结果”，应使用明确的方法调用。`【你主导】` 实践 C# event、订阅解绑和生命周期问题。

### 12.6 设计模式的学习边界

| 模式/思想 | 实际用途 | 是否采用 |
|---|---|---|
| 状态机 | 游戏流程、Boss 阶段 | 采用，`【你主导】` |
| 策略 | 锁敌、攻击、路径选择 | 采用，`【你主导】` |
| 工厂 | 根据定义创建敌人与塔 | 第二阶段采用 |
| 对象池 | 子弹、特效、后续敌人 | 采用并逐步泛型化 |
| 观察者/事件 | UI 与系统通知 | 采用，控制范围 |
| MVC/MVP 思想 | UI 不直接拥有游戏规则 | 采用思想，不强套框架 |
| 依赖注入 | 显式传递依赖、减少查找 | 学习思想，暂不引入大型容器 |

### 12.7 性能预算与验证目标

性能数字的单一事实来源为 [PERFORMANCE_MANY_ENEMIES.md](PERFORMANCE_MANY_ENEMIES.md)。总策划只锁定体验要求：正式关卡的正常战斗规模不能因敌人、群落连线、状态或 VFX 出现持续卡顿；移动端允许提供稳定 30 FPS 档；视觉池降级不能改变伤害、状态或波次结果。

验收必须记录设备、构建模式、场景规模、平均/P95/P99 帧时间、CPU/GPU 瓶颈、内存和 GC 数据。先测量再优化，不能仅凭编辑器中的体感判断，也不能把压力测试数字直接当成好玩的关卡目标。

## 15. 开发者测试与 Debug 策略

### 15.1 为什么 Unity 开发也需要测试

专职测试岗位负责系统化质量保障，不代表开发者可以不学习测试。Unity 开发至少应具备：

- 把模糊问题缩小成稳定复现步骤。
- 阅读 Console、异常堆栈和首个有效报错。
- 使用断点、条件断点、Watch 和运行时 Inspector。
- 用 Debug.Log 临时验证状态，同时避免永久日志污染。
- 使用 Profiler 区分 CPU、GPU、GC、物理与渲染问题。
- 为经济、伤害、升级、存档等高风险纯逻辑写少量自动化测试。

目标不是成为测试工程师，而是成为能独立交付、快速定位问题的游戏开发者。

### 15.2 标准 Debug 流程

```text
描述现象 -> 稳定复现 -> 缩小范围 -> 提出假设
-> 收集证据 -> 最小修复 -> 回归验证 -> 记录根因
```

禁止只靠随机改代码、反复点击 Play 或一次加入大量日志来碰运气。

### 15.3 首版需要的自动化测试

只测试最值得测试的纯逻辑：

1. ATP 足够/不足时建造与升级结果。
2. 升级分支互斥、最高等级限制和出售返还。
3. 护甲、易伤、DOT 等伤害计算。
4. 波次全部生成且存活数归零时只结算一次。
5. 存档读写、缺字段、损坏文件和版本迁移。

`【你主导】` 写每类第一个代表测试并理解 Arrange-Act-Assert；`【AI 可代办】` 在同一规则下补充大量参数化边界用例。

### 15.4 手工验证清单

- 低帧率、高帧率和暂停恢复。
- 连续快速点击建造/升级/出售。
- 子弹飞行中目标死亡。
- 敌人在同一帧死亡或泄露。
- 最后一波生成结束与最后一个敌人死亡的不同顺序。
- 场景重开、重复进入、存档损坏。
- PC 鼠标与真实手机触控。
- 多种宽高比、安全区和 UI 缩放。

## 16. AI 协作与面试能力边界

### 16.1 你必须主导的内容

- 游戏状态机与状态转换规则。
- 核心数据流和模块依赖。
- 锁敌策略、状态叠加和伤害规则。
- ScriptableObject 与运行时状态分离。
- Boss 状态机。
- 存档模型和版本思路。
- 至少一套完整自适应 UI。
- 关键 Bug 的复现、假设和根因解释。
- 项目中的技术取舍与复盘。

### 16.2 适合协作完成的内容

- 对你写的代码做 review，并指出生命周期、空引用、重复结算和性能风险。
- 提供小范围示例、伪代码或追问，引导你完成实现。
- 补齐测试边界、Profiler 检查项和移动端适配清单。
- 设计数值表、整理试玩记录和分析平衡数据。
- 辅助动画状态、粒子参数、音效触发和本地化流程。

### 16.3 AI 可以代办的内容

- 重复的配置录入、表格和文档格式整理。
- 已有规范下的简单 DTO、字段绑定和机械重命名。
- 批量生成测试数据与重复测试用例。
- Git 状态检查、分支/提交命令、变更摘要和发布说明。
- README 初稿、演示清单和构建脚本模板。

注意：Unity `.asset`、Prefab 和 Scene 的机械编辑应优先通过 Unity 编辑器或经过验证的 Editor 工具完成，不能盲目手改 YAML。

### 16.4 面试标准

新时代使用 AI 并不是减分项，无法解释自己提交的代码才是。每个核心功能完成后，开发者应能回答：

1. 为什么需要这个模块？
2. 数据从哪里来，经过哪里，最后影响什么？
3. 为什么使用事件/接口/ScriptableObject，而不是更简单或更复杂的方案？
4. 最难的 Bug 是什么，如何收集证据并定位？
5. 性能瓶颈在哪里，Profiler 如何证明？
6. 如果需求扩大十倍，当前设计哪里会先出问题？
7. AI 在其中做了什么，你如何验证它的结果？

面试学习由你主导；AI 可以扮演面试官、审阅表达和指出知识盲区。

## 18. 开发路线图与责任划分

### 阶段 0：首个纵向切片闭环

目标：在新工程中用最少内容打通“路径 -> 敌人 -> 生命/退出 -> 建造 -> 一座塔攻击 -> ATP -> 波次 -> 胜负”。

- `【已完成】` 建立项目目录、API 骨架、Prototype 场景和单敌人固定路线移动。
- `【已完成】` 完成 `Health + EnemyController`，让死亡、泄露和清场互斥且只结算一次。
- `【已完成】` 完成固定 `BuildSlot + BuildController`，只支持一座占位塔。
- `【你主导】` 完成最小锁敌、攻击、ATP、短波次和胜负流程。
- `【协作完成】` 检查 Inspector 引用、Prefab 生命周期、事件解绑和失败边界。
- `【AI 可代办】` 目录、占位资源、配置清单和回归步骤的机械整理。

完成定义：使用占位图形即可从开始完成一局短战斗；死亡/泄露、扣款、奖励和胜负均无重复结算；开发者能画出完整数据流。

### 阶段 1：第一关核心纵向切片

- 在阶段 0 的一塔闭环稳定后加入第二座塔和最小“识别 -> 效应”反应链，再逐步扩展首关内容。
- 固定塔位与范围预览。
- 6 塔基础形态，至少 3 塔完成全部特殊行为。
- 4 种敌人、5 波和 Boss 基础能力。
- ATP、建造、升级、出售、提前开波。
- 游戏流程状态机和基础 HUD。
- 子弹/特效对象池。
- 首轮新手教学与胜负结算。
- 目标单局 6-8 分钟，并验证一次教学难度免疫复苏。

完成定义：新玩家不看代码即可完成一局；无阻断流程的 Bug；首关有可理解的策略选择。

### 阶段 2：第二关系统扩展

- 多入口汇合路径图。
- 完整状态效果系统。
- 三种主动技能，战前选二。
- 感染/特殊塔位。
- 动画、粒子、音频和伤害反馈。
- JSON 存档、图鉴和免疫记忆点。

完成定义：第二关的策略不能只靠提高第一关阵容数值解决；保存重启后数据正确。

### 阶段 3：第三关展示完成度

- 分叉路线和关卡事件。
- 六塔 LV3 二选一分支。
- 多阶段 Boss 与 Timeline 演出。
- 中英文、本地化结构。
- PC/手机布局和 Android 真机测试。
- Profiler 优化和高风险逻辑测试。
- 设置、选关、完整结算与引导。

完成定义：可形成比赛包与简历演示视频；三关从开始到结算均可无编辑器干预运行。

### 阶段 4：发布与复盘

- 清理警告、临时代码与测试资源。
- 完成 README、操作说明、素材许可记录。
- 记录性能数据、已知问题和设计复盘。
- 进行模拟面试，确保核心代码均可解释。
- 决定结束项目或进入扩展阶段。

### 阶段 5：可选学习扩展

按学习价值单独选择，不默认全部实现：

- Input System 与手柄支持。
- UI Toolkit 图鉴或内部关卡编辑器。
- A* 动态寻路挑战模式。
- Addressables 与资源热更新基础。
- 程序化关卡或每日挑战。
- 排行榜、云存档或基础联网。
- 更系统的 EditMode/PlayMode 测试与自动构建。

## 19. 总体验收标准

### 19.1 游戏性

- 三关均有独立的地图结构与主要学习机制。
- 六塔具有清晰定位，至少存在三种有效组合。
- 四类核心敌人能迫使玩家改变布防。
- 资源、升级、技能和提前开波构成可理解的风险收益。
- Boss 能检验此前学到的机制，而非单纯高血量。

### 19.2 工程质量

- 无两套并行的核心建塔或战斗架构。
- 静态配置与运行时状态明确分离。
- 胜负、资源和存档没有已知重复结算问题。
- 核心对象生命周期和事件订阅可解释。
- Windows 与至少一台 Android 真机完成全流程验证。
- Profiler 无持续明显 GC 峰值或不受控对象增长。

### 19.3 展示质量

- 主菜单、教学、设置、结算和图鉴形成完整外壳。
- 关键操作有视觉和声音反馈。
- 科普内容明确区分真实知识与玩法改编。
- README、演示视频、截图和架构说明齐全。
- 开发者能在不依赖 AI 的情况下讲解核心模块与代表性 Bug。

| 存档 | JSON，本地版本化存档 |

| 语言 | 中文优先，第三关阶段补英文 |
