# 2026-10-21 已接入美术的像素精修

本次从场景、Resources、Prefab、动画与项目图标的实际引用出发，审计了 110 张可达 PNG。使用本机 Aseprite 1.3.18.6 处理在用素材，并在原项目中更新引用；原图片和 `.meta` 完整保留。

最终目录：`Assets/_Project/Art/Sprites/细胞绘制/像素精修_2026-10-21_v1/`。

## 发现与修改

| 实际问题 | 本次处理 | 数量 |
| --- | --- | --- |
| 建造菜单沿用旧图鉴符号，与战场单位外形不对应，且旧图标采用双线性过滤与压缩 | 从精修后的六塔首帧制作透明 128×128 图标，统一主体大小及留白；更新六个 TowerDefinition 的 buildIcon | 6 张 |
| 角色图集有一万至四万多种近似颜色，小尺寸下色块细碎 | 每个单位共享最多 96 色，敌人的移动与攻击使用同一色板；保持青白免疫方、洋红紫病原方、金色抗体的关系 | 22 张、220 帧 |
| 部分界面有接近不透明的 254 alpha 与透明边缘碎点，颜色重复 | 整理为最多 48 色，静态 UI 透明通道规整为 0/255，清除隐藏 RGB；保留原有文字、尺寸与布局 | 50 张 |
| 记忆脉冲、抗体标记环存在近似色与边缘残留 | 整理为最多 64 色，清理极低 alpha，保留设计需要的中间透明度 | 2 张 |
| 主界面背景使用双线性过滤与压缩 | 原始 RGBA 不变，另存新版并改用 Point、无压缩、无 mipmap 导入 | 1 张 |

共接入 81 张新版纹理，59 个项目资源文件只修改了图片 GUID 引用。本轮未修改运行时代码、玩法数值或关卡坐标。

这 75 张替换纹理的 PNG 磁盘体积从 11,150,199 字节降至 5,800,915 字节，减少约 48%。该数据仅指 PNG 文件，不代表 GPU 显存或 APK 体积；新版导入采用无压缩以保留像素边缘。

原先已经规整的暂停/1×/2×六张工具栏按钮，以及五张地图背景，继续使用已有素材。

## 风格与制作依据

核对了本地 `Docs/ART_DIRECTION.md`、`Docs/Prompts/`、已有动画与 UI 提示词，以及 Notion 的[统一美术方向与资产规范](https://app.notion.com/p/3b8c4f951620817cb407f1726dc3df97)、[防御塔](https://app.notion.com/p/3b8c4f95162081bab6b1e1759f0c43cd)、[敌人与 Boss](https://app.notion.com/p/3b8c4f95162081bdb970f8cc1fea688f)、[地图](https://app.notion.com/p/3b8c4f951620815aa491d632803bd02b)、[子弹与 VFX](https://app.notion.com/p/3b8c4f951620814581c0d8fd84c145e5)笔记。

沿用活体图鉴的卡通像素方向：温暖组织、冷色免疫细胞、墨紫轮廓、无血腥、清晰的生物结构。Notion 中较早的伪俯视、固定路线与壁垒改路描述属于历史设计；本次按当前正俯视十帧动画和 2026-10-20 本地玩法实施，不回退旧规则。

像素修改由 Aseprite Lua 完成；Python 仅用于文件与像素结果检查、生成导入元数据和替换引用。没有重新生成角色造型。

## 保留与回退

新版动画保持 640×256 图集、5×2 排列、128×128 单帧。全部 220 帧的 alpha 与旧图逐像素一致；Unity 切片、local fileID、Pivot、PPU 保留。动画 `.anim` 只替换图集 GUID，原有时序和事件保留。

素材目录中的 `制作记录~/` 保存：

- `处理计划.json`、`在用资源审计.json`：处理范围与源文件哈希。
- `Aseprite精修.lua`、`Aseprite源文件/`：可编辑源文件、共享色板与导出过程；单图源文件编号与处理计划中的顺序对应。
- `Aseprite处理结果.json`：各图调色误差、alpha 变化与图标对应关系。
- `Unity接入记录.json`：新旧 GUID、修改文件哈希与颜色统计。
- `接入前备份/`：59 个引用文件在本次替换前的完整副本，包括当时工作区已存在的改动。
- `文件完整性验证.json`：75 张原 PNG 和原 `.meta` 哈希未变、81 个新 GUID 无重复、引用文件仅改变美术 GUID。
- `角色像素前后对比.png`：每组左旧右新，下面为局部放大。

回退时按接入记录反向替换对应图片 GUID；六个 buildIcon 按备份恢复。若文件在本轮之后还有其他修改，先比较再恢复，避免直接用备份覆盖后续工作。旧素材始终保留在原位置。
