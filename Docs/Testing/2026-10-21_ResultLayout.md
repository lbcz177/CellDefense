# 胜利 / 失败 UI 超屏修复验证

日期：2026-10-21；Unity 2022.3.53f1c1。

## 原因与修复

原预制体背景为 10 倍缩放、按钮为 6 倍缩放，Canvas 使用固定像素；原适配只对手机生效。未修复版本在桌面 640×480 实际渲染中，背景左边界为 -180，标题与返回按钮被裁掉；新增边界回归按预期失败，记录保存在 Logs/ResultLayoutValidation/before.xml。

五关现统一使用 FitResultToScreen：背景 600×600、按钮 512×96、单位局部缩放，整组内容放在 800×720 的设计区域内等比适配安全区。三按钮纵向位置为 10 / -90 / -190，两按钮为 -60 / -180；底部按钮落在面板内部。窗口改变时复用 MobileSafeFrame 的渲染前刷新。

## 实际结果

| 阶段 | 结果 |
|---|---|
| 原版复现 | 专项 1/1 按预期失败，桌面越界被检测到 |
| 统一屏幕缩放后的完整 PlayMode | 39/39 通过，0 失败 / 跳过 |
| 随后微调按钮间距的最终专项 | 1/1 通过；已有用例重跑，不与 39 相加 |
| 最终专项覆盖 | 5 关 × 胜利 / 失败 × 桌面 / 手机 × 3 尺寸，共 60 组状态 |
| 窗口变化 | 结算页保持显示时切到 960×540，图片与按钮继续位于安全区内 |
| 点击与分支 | 每个可见按钮中心实际 GraphicRaycaster 命中自身；前四关胜利三按钮、第五关胜利及失败两按钮 |

三种尺寸为 640×480、1280×720、2048×928。检查实际子图片边界，而不只检查包装框；旧版在第一个桌面胜利状态就失败。完整回归也覆盖原有暂停 / 设置、购售、引导和实际三轮防守。

测试在 Logs/CodexTradingTests 独立副本执行，使用 D3D11。已实际查看修复前后 640×480 胜利图、1280×720 桌面失败及手机胜利预览。最终 5 个重点文件（控制器、包装层、测试与两个原预制体）SHA256 与主工程一致；原图片、预制体与 .meta 未改写，修改仅在运行时排布。

用户正在使用的主工程 Unity 没有被停止或切换场景。Unity 编译后重新运行或重载关卡，初始化新布局；本次不重打 APK、不操作 TapTap、不进行 Android 真机验收或 Profiler 测量。
