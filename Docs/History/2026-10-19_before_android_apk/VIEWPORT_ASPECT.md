# 战斗画面拉伸修复

日期：2026-10-19；Unity 2022.3.53f1c1。

桌面原来把 Camera.aspect 固定为棋盘 15/11，同时让相机占满窗口。实际窗口为 16:9 时，同样长度的世界坐标在水平方向会多占约 30% 屏幕像素，因此细胞和射程圈会横向拉宽。此前测试确认了铺满和坐标对齐，却没有检查屏幕上的形状比例。

## 当前规则

OpenFieldPrototypeController.ConfigureMapViewport 现在从相机实际 pixelRect 计算 aspect，并用下面的正交半高容纳完整棋盘：

`halfHeight = Max(boardHeight / 2, boardWidth / (2 * viewportAspect))`

桌面使用完整窗口；手机继续在安全区内预留 HUD 行。每帧检查所需投影，只有参数改变时更新相机；暂停时调整窗口也会生效。相机居中，网格世界坐标、塔射程、速度、障碍和寻路规则保持原值。不同窗口比例会在左右或上下留出空间。

细胞、射程圈、路径与格子点选继续共用同一相机。屏幕 UI 使用各自 Canvas 的缩放规则。

## 验证

OpenFieldWaveFlowTests 用 16:9、21:9、4:3 与竖向渲染目标检查棋盘完整、居中、所有 165 个格子往返映射、世界单位横纵像素长度相等及圆周半径一致；另测同一相机连续切换窗口比例。

ZzMobileLandscapePlayModeTests 在真实 Game 视图中检查桌面与手机布局；暂停后不重载场景，连续调整 1280×720、960×720、1600×720、720×1280，并核对相机比例、圆形与格子映射。另导出 1280×720 的旧投影重现图和修正图，以及其他横屏修正图。旧投影图由测试临时设置原参数重现，非旧版本 Player 截图。

## 背景贴图边界

五张地图原图为 1536×1024（3:2），仍按既有 15×11 关卡边界映射，保持与现有入口 / 障碍格的定位。本次修正的是世界到屏幕的投影，没有改动美术文件或重排关卡。原图像素与逻辑网格并非完全相同比例；进一步要求背景原图也按 3:2 显示时，需要同步重新核对障碍与美术位置。

历史基线见 [修复前快照](History/2026-10-19_before_viewport_fix/INDEX.md)；手机构建组件仍按用户选择暂不安装，没有 APK / 真机结果。

最终验证：EditMode 127/127、PlayMode 31/31，见 [证据报告](Testing/2026-10-19_ViewportAspect.md)。
