# 出怪口开波按钮

日期：2026-10-16。适用于现有第一至第五关开放地图。

## 已确认交互

- 每个下一波会使用的入口有一个真正的 UGUI Button，位置跟随入口，使用刚绘制的圆形细胞图片；由于地图已铺满画面，按钮向入口内侧轻微偏移，并限制在屏幕安全区域内。当前五关分别显示 1 / 2 / 2 / 2 / 3 个。
- 所有入口按钮控制同一轮。点任意一个，就按既有入口轮换规则开始整波，不是只从被点击入口出怪。
- 圆形图片下方独立显示“第 N 波 / 开始”等状态文字，不覆盖图案；图片保持宽高比。布置阶段开战关闭选塔框和放置预览。
- 按钮仅在可开波时显示。当前波仍在出怪时，整组按钮和文字隐藏，不阻挡地图点击；不允许两轮刷怪协程并行。
- **按用户选择：当前波计划出怪结束、还有残敌时，可以点击“第 N+1 波 / 提前开始”。** Boss 召唤物仍计入残敌，但不阻止提前开下一波。
- 当前波清空且尚有下一波时，照常进入布置阶段，可以继续建塔，然后从入口按钮开波。
- 最后一波启动后隐藏开波按钮；胜负时也隐藏。必须计划出怪结束且所有残敌 / 召唤物退出后才能胜利，核心归零仍优先失败。
- 顶部外置 `Start assault` 按钮已移除。左上角现用新绘制的图片状态栏显示 ATP、生命、波次，入口按钮避让其实际屏幕区域；详见 [HUD 接入](BATTLE_HUD_ART_IMPLEMENTATION.md)。Space 快捷键使用与入口按钮相同的开波判断。

## 保持的规则

提前开波时保留旧敌人与共享 WaypointPath，新一波复用这组路径；旧敌人和 Boss 的召唤请求不会因切换波次而引用被销毁的路径。只有所有敌人清空、回到布置阶段或终局时才清理路径。

每次进入下一轮只发放一次原有 betweenRoundATP：正常清场时进入下一轮布置阶段发放；提前开波则在点击时发放。不另外添加提前奖励，不重复发放。2026-10-16 起按用户要求布置与进攻均可建塔，提前开波继续保持进攻状态，详见 [战斗中建塔](LIVE_BUILD_IMPLEMENTATION.md)。

三轮资产、数量、敌人速度、ATP 配置、塔数值、壁垒额度和地图阻挡格均未修改。按钮使用 `Assets/_Project/Art/Sprites/细胞绘制/战斗UI/下一波按钮_v1/下一波_圆形细胞按钮.png`，五个场景已绑定引用，原 PNG 与 .meta 字节保持一致；沿用已有中文字体，无需手动 Inspector 接线。第一关场景创建工具也已同步图片引用。

## 地图铺满画面

五关在初始化时由 OpenFieldPrototypeController.ConfigureMapViewport 设置正交相机：视口占满 Game 画面，orthographicSize 为地图高度的一半，aspect 固定为逻辑地图宽 / 高，相机中心对齐棋盘中心。当前仍为 15 × 11、每格 1 世界单位。

完整地图会非等比拉伸至当前画面，不裁切入口 / 核心，不保留原来的外围空白。世界中的背景、单位、路线与射程圈共同使用这一映射，细胞 Sprite 与射程圈的屏幕形状也会随画面比例改变；世界坐标、寻路步长、移动速度和伤害 / 射程参数不变。建塔输入通过同一相机进行屏幕 / 世界坐标转换，血条与入口按钮也通过该相机投影定位。

入口按钮属于屏幕 UI，圆形图案不会随地图变形；位置在窗口尺寸变化时重新投影，并避让状态栏。这里的“全屏”指铺满游戏渲染视口，不强制切换 Windows 的全屏窗口模式。相机 aspect 的手动设置保持有效，直到 ResetAspect 被调用，参见 [Unity Camera.aspect](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Camera-aspect.html)。

## 已打开场景的素材引用兼容

用户反馈报错后，Editor.log 显示 `InvalidOperationException: Assign the entrance wave button artwork`，运行场景记录为编辑器临时备份。五个磁盘场景已有 Sprite 引用，但当前运行状态中的新字段为空，原校验直接中断 Awake。

现由 `OpenFieldUiResources.ResolveWaveButtonArtwork` 优先使用场景引用；缺失时加载 `Assets/_Project/Resources/OpenFieldUiResources.asset` 中的默认 Sprite 引用。该配置仍引用原圆形按钮图片，适用于编辑器和 Player，不依赖 AssetDatabase，不复制或移动 PNG。显式配置的其他按钮图片仍会被保留。场景及默认配置都缺失时才提示配置错误。
