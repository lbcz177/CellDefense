# 五关结算评分与星级（2026-10-25）

用户确认采用“击杀表现＋核心剩余生命”。满分 10000，通关后按分数给星；五关仍可自由选择，不增加前置关卡锁定。

## 规则

| 项目 | 计算 |
| --- | --- |
| 击杀分，最高 4000 | 向下取整：4000 × 已击杀的波次计划敌人数 ÷ 本关全部波次计划敌人数 |
| 核心分，最高 6000 | 胜利时向下取整：6000 × 剩余核心生命 ÷ 初始核心生命；失败为 0 |
| 总分 | 击杀分＋核心分，0–10000 |
| 三星 | 胜利，且总分 ≥ 9000 |
| 二星 | 胜利，且 7000 ≤ 总分 < 9000 |
| 一星 | 胜利，且总分 < 7000 |
| 零星 | 失败，不写入通关纪录 |

例如击杀 75/100、核心剩余 14/20，得分为 3000＋4200＝7200，二星。满血清除全部计划敌人为 10000，三星。各关敌人数与核心上限不同，统一按比例评分。

召唤物不进入计分分子或分母，即使以后调整它们的 ATP 奖励也不增加评分。漏怪、清场回收及重复退出回调均不能增加击杀数。暂停、倍速、战斗时长、ATP 余额、出售与建造次数不参与本版评分，避免拖延、囤积资源或切换倍率影响成绩。

## 关卡流程与存档

1. 进入关卡或重试，初始化本局统计，保留已存最高分。
2. 正常经过三波、末波清场且核心存活后胜利；核心归零仍优先失败。
3. 结算页显示本局得分、三颗亮／暗像素星、击杀与核心分项；按 2026-10-26 的反馈移除最高分行。同一局结算只处理一次。
4. 每关只保留最高通关分，星级按该最高分计算。重打同分、低分、失败或中途返回不会降低纪录。
5. 选关页显示每关最高分和最佳星级。未通过的关卡显示三颗暗星及“未通关”，仍可点击。
6. 前四关胜利保留“下一关”，第五关不显示；继续下一关和重试使用新场景实例。退出并重新打开后仍能读取本地纪录。

PlayerPrefs 键为 `CellDefense.LevelProgress.v1.<SceneName>.BestScore`，只允许当前五关场景名。首次通关与未通关通过键是否存在区分，不能仅以 0 分判断。没有新增联网、云存档、清空进度入口或迁移推断；旧版本没有成绩时按未通关展示。

- `LevelScoring.cs`：评分、分项、星级阈值。
